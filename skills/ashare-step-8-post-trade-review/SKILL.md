# 第8步：交易后记录与复盘

主技能 `a-share-investment-workflow` 第8步子技能。

## When to Use

- 用户主动告知实际买入/卖出（触发词：“我买了/卖了 X”）。
- 用户要求复盘某次交易，或要求对照操作当时的周报。

**触发：** 用户说“我买了/卖了 X”时。**仅在用户主动告知时执行，不主动追问持仓变动。**

## 🔴 执行纪律（本工作流强制·优先级最高）

🔴 **本节优先于本技能其余内容，冲突以本节为准。**

### 本步不可跳过的项

| # | 强制项 | 不做会怎样 |
|---|---|---|
| 1 | **对照操作当时的周报**，用当时的认知环境判断，不事后诸葛 | 事后才知道的事不能算「当时应该知道」 |
| 2 | **不改周报** | 改了就失去「当时怎么想的」这份证据 |
| 3 | 偏离原计划时**必须问原因，并记录用户原话** | 不问就复盘 = 猜测用户为什么改主意 |
| 4 | 阶段变更**当次**更新流程状态表 | 状态表滞后 = 路由错误 |

### 本步专属红线

**复盘不追责。** 目的是让下一轮判断更准，不是找谁的错。

> 全局三条硬规则（不凭记忆执行／跳过须显式写明／缺数据就停下来报）见主技能
> `a-share-investment-workflow` 《执行纪律》一节。

### 收尾自查

- [ ] 已调取操作当时的周报做对照
- [ ] 周报未被修改
- [ ] 偏离项已问原因，用户原话已记录
- [ ] 决策日志已追加（每笔追加，不覆盖）
- [ ] 流程状态表已同步（如阶段有变化）

## 固定流程

1. 确认操作事实：标的、方向、时间、价格、占仓比（不确定就问，不猜）。
2. **读当时的周报**（不是最新周报）——用 `ls --time-style=long-iso /weekly_report/*.md` 找出操作日之前生成的最新一份。
3. 把周报建议与用户操作逐项对照，判定 遵循 / 部分偏离 / 完全偏离。
4. **偏离时问用户为什么**，把用户回答的**原话**记下。
5. 追写 `$STOCK_DATA_DIR/投资决策日志.md`（只追加，不覆盖）。
6. **同步跨阶段状态表：** 若本次交易导致该标的阶段变化（首次买入、清仓、移出），更新 `$STOCK_DATA_DIR/股票台账/流程状态表.md` 对应行或移入归档区；状态表只写阶段，交易次数/成本/价格线等细节全部进个股台账。

## 铁律

- 只记事实与用户原话；**不替他解释、不评判对错**——他的逆向可能是对的。
- 事后补记必须标「事后补记」；事件发生日与记录日分列。
- 报告建议**只引用原文**，不转述。
- **不要试图改周报格式**——用户明确不希望改周报；核对是外部动作。

## 关键发现模式（值得主动指出）

同一个观察可能被两边做相反解读。例：周报把“节前缩量”当谨慎信号（降仓），用户当买入信号（押注节后回升）。这类“同数据、反结论”是日志里最有价值的记录。

## 与其他步骤的衔接

- 买入成交 → 同时进入第7步 `ashare-step-7-position-ledger` 建/更新台账。
- 每一笔实际成交都同时更新跨阶段看板 `流程状态表.md`（阶段、条件、最近更新）；卖出并清仓的标的移入归档区。
- 卖出成交 → 更新台账；确认清仓后按用户结果取消/调整持仓任务，保留历史记录（见第7步第12节）。
- 复盘发现流程问题 → 报告用户，不自行改技能。

## 输出与停止条件

决策日志追加完成即停。不改周报、不自行删除历史、不擅自调整技能。

## 🔴 阶段变更 = 更新流程状态表（三层保障）

标的进出本步（新增／移出／降级／清仓）时**当次**更新 `股票台账/流程状态表.md` 对应行，只写「名称 (代码)」；细节进单股台账。🔴 **同一代码不得出现在多个阶段行。**

三层保障：① 本要求；② `validate_ledgers.py` 台账↔状态表双向一致性（跨行重复／有台账未登记／标第5-7步但无台账）＋台账正文↔`bench.json` 门槛数据一致性；③ 周一 08:12 `台账同步`（no_agent）自动跑校验，不一致→飞书告警。

🔴 目录与 cron 是自动扫描的（建台账即纳入），**只有流程状态表是手工的** —— 唯一会漏的环节。
