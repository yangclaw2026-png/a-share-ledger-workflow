# 机械计算用 Python 前置，不占用大模型

## 适用范围
纯算术判断、无需理解语义的任务：价格阈值判定、ATR 计算、涨跌幅统计、区间触发。
典型场景：盈利保护价格观察、止盈止损线判定、组合权重计算。

## 架构
```
Python 脚本（免费、秒级、算术准确）→ 写 JSON
    ↓
大模型（仅在 REVIEW / FAULT_ONCE 时介入）
```

## 三档action 分支（cron prompt 必须按此分支）
| action | 含义 | 模型动作 |
|---|---|---|
| `SILENT` | 数据有效且未触发 | **直接结束**，不发飞书、不发邮件、不做任何判断 |
| `REVIEW` | 触发 / 疑似除权 / 部分标的失败 | 按规则复核后通知 |
| `FAULT_ONCE` | 全部标的取数失败 | 只报一次简讯，continuity 标记，避免重复报同一故障 |

## 现有脚本
- `scripts/profit_guard.py` — 盈利保护观察（阈值＝成本＋2×Wilder ATR(20)）
  ```bash
  python3 scripts/profit_guard.py --slot 11:20
  ```
  输出 `/tmp/guard_<slot>_<YYYYMMDD>.json`

## 🔴 四条硬规则

**1. 优先判断数据是否可验证，而非数据是否触发。**
任一关键数据或口径无法验证时，不得报告触发。全部失败时走 `FAULT_ONCE`，绝不能因“无数据”而静默——那样故障会被静默吞掉。

**2. 成本必须从台账「交易记录」表解析，且数量校验。**
绝不能用全文搜索「成交价」抓数字——台账正文里存在作废记录
（例如「¥64.28 为 9/30 收盘价估算的临时参考，已不再作为成本」），会抓错。

**3. 脚本本身失败 ≠ FAULT_ONCE。**
前者是「脚本没跑起来」，后者是「数据取不到”。脚本执行异常时 cron prompt 必须写明退回人工全流程核验，并在 continuity 记录脚本异常。

**4. 脚本内置旧价格线禁用清单。**
流程轮换后旧止损线必须硬编码进脚本 `FORBIDDEN` 列表，而不是只写在 prompt 里。

## 接入 cron 前必查项
| 检查项 | 失败后果 |
|---|---|
| 用真实行情回算阈值 | 阈值算错 |
| 成本来源校验（确认命中「台账交易记录」而非「内置基线」） | 阈值整体偏移 |
| 三个分支各跑一次（正常/触发/取数失败） | 静默吞掉故障 |

## 效果量级
单次模型调用从约 9–16 万 token 降到 0（90% 交易日），执行时间从约 60 秒降到秒级。
