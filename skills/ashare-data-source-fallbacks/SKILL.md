# A 股数据源限流与绕行

A 股数据接口在高频调用时会**静默限流**（返回空值而非报错）。**空值不等于数据不存在 —— 必须先换源再下结论。**

## When to Use

- 巨潮 `topSearch` 返 `orgId: None`，或 `hisAnnouncement` 返 0 条。
- 行情接口返 0 行、全市场列表为空。
- 需要读美国法案/政策原文而搜索只给二手转述。
- 任何接口报错或结果异常空。

## 🔴 执行纪律（本工作流强制·优先级最高）

**本节优先级高于本技能全部内容，冲突以本节为准。**

### 一、本技能不可跳过的项

| # | 项 | 不做会怎样 |
|:-:|---|---|
| 1 | 🔴 **接口返空 ≠ 事实不存在** → 先换源；换不到才标「未取到」，并**写明已试过哪些源** | 用静默空值下「没有这个东西」的结论 |
| 2 | 🔴 **取数用三态 `OK`/`EMPTY`/`FETCH_FAIL`，不用 `None`/空容器**；⚠️ 空 dict 是 falsy，别用 truthiness 判断 | 下游把失败当业务值 |
| 3 | 🔴 **异常处理里不许兜底成旧值或空集合** → 一律显式中止或显式上报 | 返回合法默认值比抛异常危险——下游照常算出错数字并报「正常」 |
| 4 | 🔴 **过滤器不许静默跳过**：全部纳入 + 显式 `NEED_DATA` 并列出缺哪几项 | 漏配一条 → 标的无声退出监控，叠加静默规则后完全不可见 |
| 5 | 🔴 **没有「经营现金流同比」字段，必须自算同期金额**（`cf_prev` 按 `REPORT_DATE` 精确匹配同报告期，不能取相邻条）| 误用 `MGJYXJJETZ` 曾一次令 **5 只标的 A1 判定翻转** |
| 6 | 🔴 **两个接口的过滤字段口径相反**：F10 系 `SECUCODE="600000.SH"`／估值系 `SECURITY_CODE="600000"` | 传错静默返空，像「这家没财务数据」 |
| 7 | 🔴 **裸股票代码会静默返回空数据** → 带 `sh`/`sz` 前缀，且写完取数代码先拿一只已知有数据的标的跑通 | 下游 `IndexError` 或错误数值 |
| 8 | 🔴 **写完检查器必须造坏状态证明它会报**，不能只测好状态 | 正向测试永远会过，分不清「检查在工作」与「检查没执行」 |
| 9 | 🔴 **bench.json 门槛数据必须是真算出来的实测值，禁填「暂缺」占位**；补完用 `--codes <新代码>` 单跑，把输出与文档判定表逐项对照 | 脚本与台账正文长期说两套话，无任何检查会发现 |
| 10 | **二手转述不得当一手**；只在二手里出现的说法列「待核实」而非引用；多源看似一致时回查是否同一原始出处 | 自我循环验证 |
| 11 | 🔴 **批量生成多份文件后逐个 resolve 校验相对链接**，从每个文件自身目录算真实路径 | 跨目录 `../` 错一层，只改文件名不动层数＝没修 |
| 12 | 🔴 **先分清哪些量「能算」哪些「该问」，再决定台账字段**：客观/可从权威数据算出的量一律脚本算（加权成本、持仓期峰值、回撤率），**不要做成让用户手填的字段** | 手填的客观数据随行情变而过期，且混入台账后分不清哪些是行情、哪些是风控边界 —— 用户的原话是「峰值不应该是我持仓以来的日最高值吗」 |
| 13 | 🔴 **校验器/监控检查要区分「字段缺失」与「字段在但值未设定」**；能从数据算出的字段**不应进「必填值」清单** | 把算得出的量当必填，等于逼用户填本该自动的值 |
| 14 | 🔴 **从表格单元取数时，数字必须连千分位逗号一起吃完，且单位不同的值不得再二次归一化** | `10,000 股` 被正则只吃 `10` → 渲染「仓位上限 10 股」，少位数还看不出错；再被 `cap/100` 归一化成 `100` → 「已满仓」误判成「还能加 9,900 股」 |
| 15 | 🔴 **解析字段名只认整格相等，不要用子串包含匹配** | 字段名「持仓期最高价」会匹配到另一行「盈利保护启动条件」的描述文字 → 读到参考数字当用户设定值 |

### 二、本技能专属红线

- 🔴 **「营收高增 + 经营现金流转负」在周期扩张期是典型形态**，营收越快越该警惕，不是例外。
- 🔴 **前复权价与用户台账成本可能不同口径** → 算「成本+N×ATR」前必须确认可比，否则阈值整体偏移。
- 🔴 **ATR 重算先查台账用 Wilder(20) 还是简单平均**（实测差 ¥0.23 且不随行情收敛）。
- 🔴 **「看着便宜/贵」必须落到分位**；PE/PB 绝对值跨标的不可比。多窗口一律并列报出（全样本／剔首年／近3年），只给一个数会隐藏口径分歧。
- 🔴 **2018 年前上市标的「剔首年」与「含首年」必然同值** → 不得报「首年检验通过」，须写「数据源起点限制，未能检验」。
- 🔴 **读法案先定「谁流向谁」再判标的利弊**；多条认定路径要说清哪几条被挡、哪几条仍敞着。
- 🔴 **初步禁令 ≠ 终局胜诉**，按已发生的具体救济分层陈述。
- 全局三条硬规则见 `a-share-investment-workflow`《执行纪律》一节。

### 三、收尾自查

- [ ] 每个空值都问过：是 EMPTY 还是 FETCH_FAIL
- [ ] 异常分支没有兜底成旧值/空集合
- [ ] 现金流同比是自算同期金额，不是取接口字段
- [ ] 过滤字段口径对（SECUCODE 带后缀 / SECURITY_CODE 纯代码）
- [ ] 检查器做过坏状态注入测试
- [ ] 估值结论落到分位，多口径并列，未用绝对值断言

## 二、行情

| 源 | 用法 | 坑 |
|---|---|---|
| ✅ 腾讯前复权日K | `https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param={code},day,,,520,qfq` | 取 `data[code].qfqday`（无则 `day`）。代码**必带市场前缀** `sh`/`sz` |
| ✅ 新浪实时 | `https://hq.sinajs.cn/list={codes}` | 🔴 **需 `Referer: https://finance.sina.com.cn`；返回 GBK，必须 `decode('gbk','ignore')`**，否则 `UnicodeDecodeError` |
| ✅ 腾讯实时 | `https://qt.gtimg.cn/q={code}` | 🔴 **返回 GBK**，需 `.decode('gbk','ignore')`；否则取行情会抛解码错误。字段按 `~` 切分，价格为第3 列 |
| ⚠️ 东财 `push2/clist` | 全市场列表 | 🔴 限流时返 0 行，不可用 |
| ⚠️ 东财 K线 | 日K | 🔴 已限流，优先腾讯 |

**⛔ 裸代码会静默返回空数据**：不带市场前缀时腾讯前复权接口不报错、直接返回空 `day`，下游指标计算会以 `IndexError` 或错误数值爆炸。**写完取数代码先用一只已知有数据的标的跑通**（科创板 6/9 开头→`sh`，0/3 开头→`sz`）。

**⛔ 北交所（代码 `920xxx`）另走一套前缀，且腾讯 K 线不可用**：
- 实时：腾讯 `https://qt.gtimg.cn/q=bj{code}` 可用（同样 GBK 解码）。
- **前复权日K：腾讯 `fqkline` 对北交所只返回 1 根**（写 `day,,,520,qfq` 也一样）—— 看起来像「这是只新股」，会让「近 N 日涨幅」全部算不出来。改用东财日K：
  `https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=0.{code}&fields1=f1,f2,f3&fields2=f51,f52,f53,f54,f55,f56,f57&klt=101&fqt=1&end=20500101&lmt=520`
  🔴 北交所的 `secid` 市场号用 **0**（与深市同）。行结构是**字符串**：`data.klines[i] = "日期,开,收,高,低,量,成交额"`，必须 `split(',')` 后再转 float。
- 涨跌幅限制 **±30%**（不是沪深 10%/20%），同一段区间内北交所标的涨幅天然更大。
- 小市值北交所标的（<30亿）+ 30cm 弹性，本身就是「题材属性」信号 —— 报涨幅时同时报市值，避免把弹性当成产业景气。

**⛔ 前复权价与用户记录的成本可能不同口径**：分红送转会使 K 线回溯调整，而用户台账里的成交价不会跟着变。**程序化算阈值（如成本＋N×ATR）前必须确认两者可比**，否则阈值会整体偏移。脚本只做机械跳变检测并标记疑似除权，是否调整口径需回公告核实。

**新浪列序**：0名称 1今开 2昨收 3现价 4最高 5最低 … 8成交量 9成交额。
🔴 **涨停/跌停时现价与昨收数值相同** → 涨跌幅必须算 `(现价/昨收-1)`，**不能直接拿现价列当涨幅**（本项目已踩过一次）。

## 三、估值分位

✅ 东财 `datacenter-web` `RPT_VALUEANALYSIS_DET`，`pageSize=500` 翻页（`count` 上限 2123 条），`filter=(SECURITY_CODE="600000")`。字段：`PE_TTM`/`PB_MRQ`/`TRADE_DATE`/`TOTAL_MARKET_CAP`。

🔴 **数据起点固定 2018-01-02**：2018 年前上市的标的，上市首年样本不在库内，**「剔上市首年」与「含上市首年」必然算出同一个数**。此时**不得报为「首年检验通过」**，须写「数据源起点限制，未能检验」。

📎 完整规则见 `references/valuation-percentile-rules.md`：分位口径、PB/PE 背离处理（含高 ROE 成长股例外、PB≡PE×ROE 恒等式、不得用当期 ROE 分档切口径）、**PB 分位只作警示不作否决**（🟡≥90%/🔴≥98%）、**ROE 周期标签**、估值消化检验，以及回溯「历史上何时满足某阈值」时必须用 point-in-time 扩展窗口（否则前视偏差）。

**⚠️ 必做数据质量核查**：科创板/创业板新股上市首年 PB 可达 40~50 倍（净资产小），会压低分位。做法：剔除「上市首年且 PB>20」样本后重算，**报告中同时给出两个分位**。差异不大 → 分位稳健。

🔴 **`PE_TTM ≤ 0`（滚动窗口仍亏）时不得报 PE 分位**：分位函数过滤正数样本后，负现值会算出 `0%` 或 `N/A` 这类**假分位**，看起来像「全历史最便宜」。正确输出：「**PE 为负（TTM 仍亏），PE 分位不可用 → 估值判断只用 PB**」，并说明 TTM 为负通常是**滚动窗口仍含上一年度亏损**——当期已扭亏也一样。
实测：某正极材料标的 2026H1 已扭亏（扣非 +139.7%），TTM 仍 **−56.7** → 只能报 PB 分位 85.6%。
⚠️ 同理，`PB_MRQ` 也须先确认非负；两个都不可用时报 `NEED_DATA`，不猜。

## 三·二、财务指标与上市信息（东财 F10，一次取多期）

| 用途 | 调用 |
|---|---|
| 主要财务指标（多期） | `datacenter-web.eastmoney.com/api/data/v1/get?reportName=RPT_F10_FINANCE_MAINFINADATA&columns=ALL&filter=(SECUCODE%3D%22600000.SH%22)&pageNumber=1&pageSize=14&sortColumns=REPORT_DATE&sortTypes=-1` |
| 上市日期 / 主营 | 同域 `reportName=RPT_F10_BASIC_ORGINFO&filter=(SECUCODE%3D%22600000.SH%22)` → `LISTING_DATE` / `MAIN_BUSINESS` |
| ⭐ **主营构成（按产品/地区）** | 同域 `reportName=RPT_F10_FN_MAINOP&columns=ALL&pageSize=60&filter=(SECURITY_CODE%3D%22600001%22)&sortColumns=REPORT_DATE&sortTypes=-1` → `MAINOP_TYPE`（2=按产品）/ `ITEM_NAME` / `MAIN_BUSINESS_INCOME` / `MBI_RATIO` / `GROSS_RPOFIT_RATIO` |

🔴 **同一响应里两个「百分比」字段的单位可能不一样**：主要指标系的 `XSMLL`（毛利率）是**百分数**（`8.23` = 8.23%），而主营构成系的 `MBI_RATIO`（收入占比）与 `GROSS_RPOFIT_RATIO`（毛利率）是**小数**（`0.98` = 98%、`0.082` = 8.2%）。按百分数直接渲染会把 98% 印成「占 1.0%」—— 数字看着合理、错得不明显。
判据：**占比合计应≈1.0（而不是 100）**；不确定就先把原始值 `print` 出来再格式化。

🔴 **字段名不是直觉名**，用直觉名会全取到 `None`（字段存在但值为空，接口不报错）：
`TOTALOPERATEREVE` 营收｜`TOTALOPERATEREVETZ` 营收同比｜`PARENTNETPROFIT` 归母净利｜**`KCFJCXSYJLR` 扣非净利**｜`KCFJCXSYJLRTZ` 扣非同比｜**`NETCASH_OPERATE_PK` 经营现金流净额**｜`ROEJQ` ROE｜`XSMLL` 毛利率｜`ZCFZL` 资产负债率。`REPORT_DATE` 带时间戳，取前 10 位。

🔴 **没有「经营现金流同比」字段，必须自己算。** 响应里有个 `MGJYXJJETZ`（每股经营现金流同比增长率），**名字像但结果不是**：实测某标的 2026H1 现金流 3.20 亿 vs 2025 中报 2.45 亿 = **+30.6%**（与半年报原文 +30.68% 吻合），而该字段给 **−3.5%**。拿它当现金流通比会**成批误判 A1**（曾一次令 5 只标的结论翻转）。

正确做法：取**本期与去年同期的 `NETCASH_OPERATE_PK`** 自行计算 ——
```python
cftz = (cf_cur - cf_prev) / abs(cf_prev) * 100
```
⚠️ `cf_prev` 必须按 `REPORT_DATE` **精确匹配同报告期**（`2026-06-30` 配 `2025-06-30`），不能取列表相邻条 —— 相邻条是上一季报，算出来是环比不是同比。

📎 **批量复筛直接用 `scripts/rescreen_candidates.py <代码...>`**：一次算出 PB 全样本分位、PE 近 3 年分位、扣非占归母、A1 与 B3 双口径判定并输出交叉通过清单，无需重写取数逻辑。

🔴 **两套接口的过滤字段口径是反的**：F10 系（MAINFINADATA / BASIC_ORGINFO）必须传 `SECUCODE="600000.SH"`（带市场后缀）；估值系 `RPT_VALUEANALYSIS_DET` 必须传 `SECURITY_CODE="600000"`（纯代码）。**传错另一个会静默返空**，看起来像“这只股没有财务数据”。

⚠️ **A+H 标的的 H 股报价**：`push2.eastmoney.com/api/qt/stock/get?secid=116.{港股代码}`（`f57` 代码 / `f58` 名称 / `f116` 总市值）。🔴 **价格字段 `f43` 的缩放（港股常见 ×1000）必须先与已知报价核对再用**，否则 A/H 溢价会算错。

## 四、海外（法案/政策）

| 场景 | 源 | 备注 |
|---|---|---|
| 美国国会法案 | 🔗 `https://www.govinfo.gov/content/pkg/BILLS-{ Congress }hr{NNNN}ih/html/BILLS-{ Congress }hr{NNNN}ih.htm` | ✅ **可直接 curl 下载全文**（HTML→去标签→实体解码），比二手转述可靠得多。**本项目已因此推翻过自己的结论** |
| 已生效法律的配套清单/指定机制 | 律所客户 alert、立法追踪机构（BillsTrack、PoliticPro 等） | 搜不到法条原文时用这类**专业二手**定位到“哪条机制、什么条件、什么期限”，**但结论仍需回原文或官方公告核对** |
| 上交所 IPO 审核 | 🔴 `query.sse.com.cn` 返「SOA service is null」；`listing.sse.com.cn` ERR_CONNECTION_CLOSED | 🔴 **只能用媒体源**，且须注明来源与日期 |

### ⛔ 读法案原文的正确顺序：先定「谁流向谁」，再判标的利弊

政策风险最容易被读反。拿到原文后按此顺序：

1. **先定位限制对象与流向**——限制的是哪一国的资本/技术/IP 流向哪一国，而不是“这个行业被限制”。
2. **再标标的在链路哪一侧**——被限制方与经由方风险方向**可能完全相反**（主体不合规 ≠ 与之交易不合规）。
3. **数清认定路径有几条**，别只看到其中一条。**多条路径时，明确说“哪几条被现有措施挡住、哪几条仍敞着”**；只报被挡住的那条会给出虚假的安全感。
4. **找法定截止日**（指定名单的公布期限等）。律所与官方常强调“**这是法定期限而非自由裁量**”——**有硬日期的政策风险应作为台账里的待办时点写进去**，不只写在风险栏。

### ⛔ 区分“初步禁令/暂缓”与“终局胜诉”

诉讼进展要按**已发生的具体救济**分层陈述，**不得把阶段性进展说成风险解除**：

- 已获初步禁令 → 表述为“在司法程序期间免受即时不利影响”，并列出**尚未裁决的具体诉求**（认定无效/撤销/移出名单往往一个都未判）。
- 同时记录**判决理由**（是否倾向实体胜诉）与**下一步法定节点**。

### ⛔ 搜索会被二手噪音污染，政策类检索尤其明显

同一议题常有大量互相转述的聚合页，**结论可能来自同一篇被反复搬运的稿子**（等于自我循环验证）。

- 判据：**结论是否在一手来源上出现过**。只在二手里出现的说法，**列为待核实而不是引用**。
- 多源看似一致时，**回查它们是否指向同一原始出处**；若如此，**当作单一来源**对待。
- 检索失败时把“未核实到”写清楚，**不要用模糊的二手表述填空**。

## 六、财务指标接口：一个不能用的字段

东财 F10 主要指标 `RPT_F10_FINANCE_MAINFINADATA`（filter=`(SECUCODE="600002.SH")`，sortColumns=REPORT_DATE、sortTypes=-1）可一次取到 A1 全部数据：

| 字段 | 含义 |
|---|---|
| `KCFJCXSYJLR` | 扣非净利润（**金额**）|
| `KCFJCXSYJLRTZ` | 扣非同比（%）|
| `NETCASH_OPERATE_PK` | 经营活动现金流净额（**金额**）|
| `PARENTNETPROFIT` | 归母净利润（算扣非占比用）|

🔴 **`MGJYXJJETZ` 不可当作「经营现金流同比」用**：实测某标的 2026 中报现金流同比自算 **+30.6%**（与半年报记录吻合），而该字段给 **−3.5%**。

✅ **正确算法**：取 `REPORT_DATE` 为 `2026-06-30` 与 `2025-06-30` 两期的 `NETCASH_OPERATE_PK`，直接算同期金额同比：`(本期 − 上年同期) / |上年同期|`。
⚠️ 误用该字段曾导致 **多只标的 A1 判定翻转**。

## 七、估值分位：PE「全历史」与「近3年」结论常相反

- B3 的 PE 分支要求 **近3年** 分位 ≤50%，而方向档案里存的多是**全历史**分位 → **不可直接套用**。
- 实测某标的：PE 全史 63.8%（看着便宜）｜**近3年 81.4%**（其实贵）。
- 正确重算：东财 `RPT_VALUEANALYSIS_DET` 日度 `PE_TTM`/`PB_MRQ`，按日期切窗口后算百分位。

🔴 **PE/PB 绝对值跨标的、跳商业模式不可比——只有分位可比**。同一批持仓实测：

| 标的 | PE_TTM 绝对值 | PE 近3年分位 | PB 分位（剔首年） | 读法 |
|---|---|---|---|---|
| 标的A（制造业） | **59.3**（看着便宜）| **85.7%** | 82.1% | 制造业历史 PE 基数低 → 绝对值低但**相对最贵** |
| 标的B（成长股） | **225.1**（看着吓人）| **9.8%** | 64.4% | 成长股历史 PE 高 → 绝对值高但**相对便宜** |

**任何“看着便宜／看着贵”的表述必须先落到分位**；按绝对值排序选股会同时放过贵股、误杀便宜股。这也是 B3 要双口径（PB 与 PE 各一套）的根本原因。
⚠️ 有多个窗口时**一律并列报出**（全样本／剔上市首年／近3年），只给一个数会隐藏口径分歧。

🔴 **重算 ATR 类阈值（如“成本＋N×ATR”）必须与台账对齐 ATR 算法**：常用两种，结果不同——**Wilder(20)** 与**简单平均 TR**。实测同一标的同一窗口：Wilder → ¥57.58，简单平均 → ¥57.35。**阈值重算先查台账用的是哪个算法**；表里没写就先补上，否则每次重算都偏差一个恒定小额，且误差不随行情收敛。

## 六、⭐ A1 基线过期检测：给门槛脚本加公告扫描

**问题**：`candidate_gate.py` 只拉前复权日K，A1 基线与估值分位都写在 `$STOCK_DATA_DIR/bench.json` 里（基准日固定）。财报披露后，每周两次的门槛复查**根本不会发现**（A1 不会变，只有股价波动间接影响 B1/B2/B5）。

**修法**：给脚本加一步公告扫描（零 token，Python 层）——

```python
A1_BASE_DATE = "2026-09-30"          # 来自 bench.json → constants.a1_base_date，与台账基准一致，过期即提醒
REPORT_KEYS  = ("季度报告","三季度","三季报","半年度报告","半年报",
                "年度报告","年报","业绩快报","业绩预告","主要经营数据")
# 筛选：notice_date > A1_BASE_DATE 且 title 命中关键词
# 输出：rec["new_reports"]/rec["report_stale"]；主 JSON 加 report_alerts + report_fetch_failed
```

**四条设计铁律**：
1. 🔴 **不改 gate 判定**。有新财报时 A1/A2/B1-B5 仍按旧基线算，**另起一段**提醒“📄 基线过期”，并标注“基线为 <A1_BASE_DATE> 数据”。改判定会把“最新财报”与“当前门槛”两个口径混在一起，无法归因。
2. 🔴 **取数失败 ≠ 无公告**（`None` vs `[]`）——分两个字段报出，失败要明说。
3. 🔴 **取了就不要让模型再查一遍**。prompt 里必须写“不要自己再去查公告”，否则白花一轮工具调用。
4. **正向测试必须做**：把基准日**提前**到上次财报日之前（如 2026-06-30），应能抽到半年报；不做就无法区分“真的没公告”和“筛选写错”。

## 七、🔴 默认参数陷阱：函数默认值在定义时绑定

```python
def check_new_reports(code, since=A1_BASE_DATE):   # 🔴 定义时就把值锁死
    ...
cg.A1_BASE_DATE = "2026-06-30"      # 改全局（或改 bench.json 的 constants.a1_base_date）
cg.check_new_reports("600000")       # 仍用 2026-09-30 ❌
```

**症状极隐蔽**：正向测试返回 0 条，看起来像“接口真的没返回那段公告”，实际是筛选基准没生效。差点归因于“接口只返回最近50条”。

✅ 修法——函数内**运行时**解析全局：
```python
def check_new_reports(code, since=None):
    if since is None:
        since = A1_BASE_DATE      # 运行时取值
```

⭐ 凡“可配置常量 + 用它做默认参数”的组合都要查一遍。

## 五bis. ⛔ 行情接口返回结构：先确认行是列表还是 dict

不同接口的同一「日K」概念返回结构不同，按直觉写属性访问会**静默返回空值**而不是报错：

| 源 | 每行结构 |
|---|---|
| 腾讯 `fqkline` 的 `qfqday` | **列表** `[日期, 开, 收, 高, 低, 量]` → 用 `r[0]` / `r[3]` |
| 部分接口 / 自己构造的 dict 化数据 | dict `{"date":…, "high":…}` → 用 `r["date"]` |

⛔ **拿错结构的表现是静默失败**：写成 `r.get("high")` 作用在列表上恒为 `None`，函数不抛错、只返回「无数据」，下游看起来像「接口没返回那段数据」。写完先 `print(type(row), row[:4])` 确认一次。

⛔ **派生指标（元组/多元组）解包顺序必须与构造顺序一致**。`max(rows, key=lambda x: x[1])` 在 `rows` 为 `(日期, 最高价)` 时返回的是 `(日期, 最高价)`；写成 `peak, date = max(...)` 会让 `peak` 拿到**日期字符串**，后续 `px / peak` 才抛 `TypeError: float / str` —— 报错点离出错点很远。

🔴 **改了函数返回元组个数就必须同步改所有调用点的解包**，并清 `__pycache__`：旧 `.pyc` 会让改完的代码看起来「没生效」，把你引向错误归因（本项目曾因此误以为修复未落盘，转而去查数据源）。

## 五、铁律

1. **接口返空 ≠ 事实不存在。** 先换源；换不到再标「未取到」，并写明已试过哪些源。
2. **二手转述不得当一手。** 媒体称「营收 X 亿」需回财报原文核对。
3. **下载一手 PDF 后本地 `pdftotext -layout -enc UTF-8` 解析**，比在线抽取稳定。
4. **交叉验证**：价格用两源核对（腾讯K线 + 新浪收盘）。
5. **报告缺口时列出已试过的源**，便于下次不重复踩。
6. **curl 落盘要校验文件存在**（`-o` 后接 `wc -c`），否则后续 `open()` 抛 `FileNotFoundError`。
7. **⛔ 批量用同一模版生成多份文件后，逐个 resolve 校验相对链接。** 同一模版套用到不同目录时，跨目录引用的 `../` 层数极易错一层；**从每个文件自身所在目录算真实路径**，只看链接文本会漏。只改文件名不动层数＝没修。
8. **⛔ 搜索结果与真实需求可能错位。** 搜“某公司某事项进展”会翻出该公司同期无关事件的公告（找诉讼进展翻出另一件事）。**逐条读标题再取原文**，不要假设搜到的都是要找的那件事。
9. **⛔ 从台账/文档里取参数，只能解析结构化记录表，且必须做交叉校验。** 全文搜索关键词会命中**作废的历史记录与说明性文字**——台账里写着「¥64.28 为收盘价估算的参考，已不再作为成本」时，按关键词抓数字会抓到 64.28 而非真实成交价，下游阈值/盈亏全部偏移。做法：定位到表头（如 `序号|日期|方向|成交价|数量`）后只在表内解析，并用**数量等字段反向校验**命中行；解析失败必须回落默认值并在输出里标记来源，**不猜**。
   - 🔴 **行结构必须先 `print` 出来确认，不能按直觉定下标**：同一张表里 `| 第7步 | 字段名 | 第7步 | ✅ | 值 |` —— 取 `cells[4]` 拿到的是**状态标记**不是值（值在**末格**），会把 `✅`/`⬜` 当参数。同理正文表格的字段名常在**第二格**（首格是「第7步」），把正则锚定到首格会**永远匹配不到 → 检查恒真**，看上去全绿其实没跑。
   - 🔴 **占位词必须列入拒绝清单**：`待商定/待补充/参考/通用默认/实算/建议` —— 否则会把描述文字里的**参考数字**当成用户设定值（曾把「参考：样本区间最高收盘 119.17」当成用户设的峰值，误报 RED 告警）。
10. **⛔ 定时任务里算 cron 触发次数，不要手写日期区间判断。** 用 `croniter` 或 `cronjob_manage list` 核对真实行为：`croniter` 拒绝 `26-31` 这类 dom区间（会报 out of bands），而 Hermes 自己的调度器支持并归一化显示。手写“按周几算每月次数”容易把 `* * 1`（仅周一）误判成每天。**拿不准就看 `next_run_at`，它才是真实下一次触发时间。**
11. **⭐ 新写的检查器必须“造出坏状态”证明它会报，不能只测好状态。** 正向测试（喂合规数据→无告警）永远会过，无法区分“检查真的在工作”与“检查根本没执行”。做法：**人为制造一个该被抓的错误状态**（删一行引用、传一个不在字典里的代码、把基准日提前到上次财报之前），确认它真的报出、且报的内容指向正确对象，再还原。本项目已有三次因此发现真问题。
12. **⛔ 异常处理里不许「兜底成旧值」或「兜底成空集合」。** 返回一个*看起来合法*的默认值，比抛异常危险得多 —— 下游无从分辨，会照常算出一个错数字并报告「正常」。实测四种等价死法：
    - 权威源读不到 → 回落到内置基线（成本、阈值类脚本里，这会让「成本 + N×ATR」算出错的触发线，漏报也误报）
    - 配置文件损坏 → 返回空 dict（远端同步类脚本里会让每份台账各建一份重复文档）
    - 被校验的文件语法错 → 返回空集合（校验器里会让「检查没跑」显示成「全部通过」）
    - 找不到基线定义 → 返回 `({}, src)`（改写类脚本里会让下游把整个基线覆盖成空）
    ✅ 一律改为**显式中止或显式上报**。权威数据（成本、基线、远端 id 映射）读不到就报故障，**绝不用硬编码旧值凑一个数出来**。
13. **⛔ “没校验到”必须与“校验通过”分开报。** 校验器里收集一个降级清单（哪些检查因取数失败没跑上），在末尾单独成段输出并让**退出码非零**。否则「上面全是 ✅」会被读成全部合格，而实际情况是有一整项根本没执行。
14. **⛔ 取数结果用三态表达，不要用 `None` / 空容器。** 统一 `OK` / `EMPTY`（接口通、业务上确实没有）/ `FETCH_FAIL`（接口不通、超时、结构变更）。后两者在下游是完全不同的动作：前者按“无数据”处理，后者必须上报。⚠️ 空 dict 也是 falsy，别用 truthiness 判断。
    📎 可直接复用：仓库顶层 `scripts/data_guard.py`（三态容器 + 重试 + 告警文案生成，带自检）。
15. **⛔ `except: pass` 会把诊断信息全丢。** 至少把异常类型与文本存进旁路字典，附到最终输出的失败原因里 —— 否则用户只看到「取数失败」，无法判断是网络问题还是接口改版。
16. **⛔ 监控脚本里的过滤器不得“静默跳过”。** 形如 `if code in DICT: 纳入` 的写法，漏配一条数据就把标的**无声无息地排除在监控之外**（无报错、无告警，叠加“无变化则静默”规则后完全不可见）。改为**全部纳入 + 显式缺数据状态**（如 `NEED_DATA` 并列出缺哪几项）——把“漏配”从隐型失败变成可见提醒。**用户忘了补数据时会收到告警，而不是以为一切正常。**
17. **⛔ 门槛数据必须是真算出来的实测值，禁止填“暂缺”占位。** 脚本只读 `bench.json`，**台账/文档正文写的数不参与计算**——两者不一致时**没有任何检查会发现**，监控与文档会长期说两套话。实测：方向相对强弱填 `0.0` 占位 → `B4（相对中位≥0）` 恒触发且输出 `rel_pt: 0.0`，而台账正文写着 `B4❌ −6.93pt`。无历史起点可回溯时也要**先算真值**（取固定日历锚点如当季首日，对同方向全部标的算同一区间涨跌再取中位），不得用占位代替。**补完数据后的强制自检**：用 `--codes <新代码>` 只跑该标的，把输出的触发项/action 与文档里的判定表**逐项对照**；不一致就改 `bench.json`，不是改文档。
