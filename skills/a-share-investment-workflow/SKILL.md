# A股投资研究全流程（主技能 / 阶段路由）

本技能只负责一件事：**判断当前处在流程的第几步，以及这一步该做什么**。每一步的具体做法由对应子技能承接；本技能只做阶段判定、路由与边界，不重复细节。

## When to Use

- **用户说“我们开始股票投资工作”（开场语）或要求“调主流程”** —— 按下方《开场协议》展示状态表与工作流程，并询问今天做哪一步；**不得自行开工**。
- 用户提出产业方向、要求整理/比较候选公司、判断是否值得跟踪。
- 用户要求评估买入/加仓、复盘，或问“现在到哪一步了”“下一步做什么”“调主流程”。
- 用户报告对某只股票的实际操作（买入/加仓/减仓/卖出）后，需要更新阶段记录。
- 需要确认某只标的当前所处的阶段。

## 🔴 执行纪律：严格按技能规定执行，不得跳步（本工作流强制）

**本节优先级高于本技能全部内容，冲突以本节为准。**

### 一、三条硬规则（全局唯一权威，各子技能只引用不重复）

1. **进入某一步 → 必须先 `skill_view` 调出该步子技能，按其《执行步骤》逐条做完。**
   不凭记忆、不凭印象、不凭「上次做过类似的事」。技能文本是唯一权威，记忆不是。
2. **子技能里标注「必做」「不可跳过」「必须」的项，一律执行，不允许省略。**
   要省略时必须在输出里**显式写明**：「⏭️ 按我的判断跳过 <某项>，理由：X」。
   🔴 **默默不做 = 违规。** 用户可以接受你判断某项不适用，但看不见它被跳过。
3. **缺数据 / 取数失败 / 前置条件不足 → 停下来报，不硬推。**
   正确：`⚠️ NEED_DATA：缺 X，无法执行第 N 项，等你补充`。
   错误：用推断补上、跳过该项继续、或基于残缺数据给结论。

### 二、各步不可跳过的项（详见对应子技能《执行纪律》一节）

第1步 确认方向范围才开工｜第2步 结论带来源+日期+口径｜第3步 入池依据+移出条件｜
第4步 双向核验、低分位≠可入｜第5步 建台账即建、方向起点基准、A1+A2 必过｜
第6步 **不得自动启动**、三阶段顺序不可变｜第7步 台账为成本唯一权威源、读不到即报故障｜
第8步 对照当时周报、不改周报、偏离问原因记原话｜横向 通知走 `ashare-notification-spec`、飞书总结类用交互卡片。

### 三、边界（不得自行放宽）

- 助手永不下单。买卖全部由用户决定和执行。任何「分析结论」都不是交易授权。
- 🔴 **第6步门禁不能自动启动**。用户不主动发起，就停在第5步。
- 持仓数据不上云：`持仓中/` 永不上传飞书云文档。
- 价格波动（跌、破均线、回撤扩大）**一律不是**失效条件，只触发复核；失效只由公司端证据判定。

### 四、违规自查（每次收尾前）

- [ ] 本步每个「必做/必须/不可跳过」项都执行了，或显式标注了跳过理由
- [ ] 每条结论都标了来源与日期（或明确标「待核实」）
- [ ] 事实 / 推断 / 假设 / 待核实 四类分开写了
- [ ] 没有编造数据；取数失败处写的是 FETCH_FAIL 而非「无变化」
- [ ] 没有替用户做买卖决定，也没替用户选下一步

发现漏项 → 补做或写明跳过理由。**不许沉默。**

## 不可逾越的边界

- 研究方向由用户提出。不得自行选题或在用户确认研究范围前启动产业研究。
- 先大后小：先推进主流程；不阻塞主流程的参数、模板和边缘情况留待真实运行。
- 投资分析、评级、门禁和提醒都不是交易授权。助手永不下单；买卖均由用户决定和执行。
- 用户报告实际成交后才建立/更新持仓台账或相关任务；候选股不算持仓。
- **自动通知渠道固定要求：** 所有自动化通知（含正常结果和失败通知）投递至用户飞书私聊。创建/修改/恢复自动任务时必须显式指定已验证的 Feishu chat_id，不使用 `origin`、WebUI 来源或默认投递；无变化时按任务静默规则不发空通知。
- 把事实、推断、假设和待核实项分开；结论允许为待核实、不跟踪或不交易。

## 开场协议（触发：「我们开始股票投资工作」）

固定五步走，**不跳步、不自行开工**：

1. **读状态表** `股票台账/流程状态表.md`；缺失或明显过期时先按个股台账重建并说明。
2. **展示流程状态表**（在流程中的股票及各自阶段，含已移出/已清仓）。
3. **调出待办**：读 `候选/` 与 `持仓中/` 下所有台账的「待办与关键时点」，汇总在等的事件、日期、待决策项。🔴 **只报台账里写的，不凭记忆或 cron prompt 补**；某标的无台账则标注「台账缺失待补」，不得跳过不提。
4. **询问**「今天想做哪一步的工作？」—— 只问，**不替用户选**，不预先展开任何一步内容。
5. **用户指定后**，先 `skill_view` 调出对应子技能（映射见《阶段总览》），再按该子技能开始工作。

**输出格式（固定）：**

```
【流程状态表】
| 标的 | 代码 | 当前阶段 | 台账 |
…（在流程中的逐行列出）
已移出 / 已清仓：（有则列，无则写「无」）

【待办与关键时点】（从 候选/ 与 持仓中/ 台账汇总）
| 标的 | 在等什么 | 关键日期 | 待决策项 |
…（逐条列出；无则写「无」）

【工作流程】1-8 步 + 横向规范（名称见《阶段总览》，一行一项）

今天想做哪一步的工作？（回复步骤号或名称即可）
```

🔴 **只发主流程，不发子技能内容**：默认只展示上述两块，不顺手展开第1–8步细节 —— 子技能是「进入某环节才调出」的内部资料。用户主动问某几步有哪些时可展开。

🔴 **开场禁止**：展开某步细节、替用户决定做哪步、直接开始研究或改台账。开场只在用户发起时执行，不主动触发。

| 2 | 全球产业分析 | `ashare-step-2-global-industry` | 方向与边界已确认 | 带来源/日期/口径的产业证据与前瞻判断 |

| 5 | 候选跟踪与买入时机 | `ashare-step-5-tracking-timing` | 标的进入跟踪 | 状态（继续跟踪 / 进入买入前讨论 / 暂缓 / 移出）+ 等待证据与复核节点 |

## 如何判断当前在第几步

按证据状态判定，不按时间判定；每只标的分别记录自己的阶段。

- 方向尚未与用户确认 → 第1步
- 方向已确认、尚无候选池 → 第2–3步
- 候选池已有、用户尚未选定标的 → 第4步
- 标的已进入跟踪、约定买入条件未到 → 第5步
- 约定条件已达或接近、且用户希望评估该笔 → 第6步
- 用户已报告实际成交 → 第7步
- 存在待复盘的已发生交易 → 第8步

阶段变化由关键证据或约定条件驱动，不由单日涨跌机械切换。暂缓后不因信息补齐自动恢复；移出后不自动恢复。

## 阶段记录要求

每只标的记录：**当前阶段**（记在流程状态表），以及**阶段依据、关注数据、下一步条件、失效/淘汰条件**（记在该股台账）。候选跟踪不等于持仓；候选观察提醒与持仓风险提醒分开。可同时维护多只标的、各处于不同阶段；只为阶段变化和重要新证据输出。

## 流程状态表（只记股票与阶段）

**`$STOCK_DATA_DIR/股票台账/流程状态表.md`** 只回答一个问题：“现在有哪些股票、各自在第几个阶段”。**任何具体状态（买入/卖出次数、成交明细、成本、买入计划与卖出线、证据、风险、复盘）都不进状态表，一律进该股台账。** 字段与维护规则见 `references/status-board.md`。

**读（每次调用本技能必做）：** 凡用户要求“调主流程”、问当前到哪一步、问下一步做什么，**先读该表**，列出全部股票及其阶段（含已移出/已清仓），再回答后续问题；不得凭记忆或单股台账拼凑现状。表缺失或明显过期时，先按台账重建并说明。

**写（只在阶段变化时写）：** 标的阶段发生变化（含新标的进入、移出、清仓）时，当次改对应行；不改“依据/条件”之类字段——那些在台账里。更新本表不推送通知。

## 单股台账与建档索取

每只股票一份 `股票台账/{候选|持仓中}/{股票名}_{代码}_跟踪台账.md`，按模板 **`股票台账/模板/单股跟踪台账_模板.md`** 建档（模板末尾附《建档索取清单》）。

- **新建档时必须按该清单向用户索取信息**，未提供的写“待补充”，不推算不杜撰。

### ⭐ 台账建立时点（本工作流明确强调的硬规则）

**标的进入第5步“候选跟踪与买入时机”时就必须建立单股台账**，不得以“方向记录文档”代替，不得等用户实际买入。

- 台账路径：`股票台账/候选/{股票名}_{代码}_跟踪台账.md`（档案类型写“候选跟踪”）；用户报告成交后转 `持仓中/`。
- **台账必须包含待办与提醒**：该标的在等什么事件、什么日期、要做什么决定、失效硬信号、下一步条件。这些属于台账内容，不得只存在于 cron prompt。
- **每个跟踪标的至少要有**：原始理由、核心假设、传导链、可观察指标、失效条件、**门槛状态（A1/A2 + B1–B5，估值条件＝B3 双口径）**、待办与关键时点、已核实证据（带来源与日期）。
- 用户报告成交后，在同一份台账内追加交易记录并把档案类型改为“持仓中”，**不新建文件**。

## 输出与停止条件

- 每阶段明确：已核实事实、推断/假设、待核实证据、当前结论和下一阶段入口。
- 一旦完成当前阶段目标，即停止扩写非阻塞规则；如无真实研究方向，不自行启动下一阶段。
- 用户询问"下一步"时，指出当前所在阶段和一个最高优先级的下一动作，不重新打开已确定的所有细节。

## 验证与限制

这是试行中的流程，尚未通过完整案例验证，也不保证投资结果。每次研究应保存可追溯的来源、日期与口径；只有实际使用暴露的问题才进入流程修订。

**执行**：`python3 scripts/sync_ledgers_to_feishu.py`｜目标文件夹 token 从环境变量读（`FEISHU_FOLDER_TOKEN` / `FEISHU_FOLDER_SUBDIR`，见 README），🔴 **禁止新建飞书文件夹**；`feishu-doc-sync` 只讲通用写法。

**cron**（示例，按需自建）：台账同步（示例为周一 08:12，no_agent 零 token）自动执行；判定更新后随门槛复查 cron 走。
🔴 **cron 引用写完整任务名，永不写 ID**（改名将失效，已踩坑两次）；**简称会匹配失败**，须逐字照抄 `jobs.json` 的 `name`。

**IM 格式**：总结/报告/表格类一律 `interactive` 交互卡片，不用 `text`/`post`。三个坑（`card`+`content` 双写、`note` 内只用 `lark_md`、`table` 组件不可用用 `column_set`）见 `feishu-im-message`。

**🔴 校验**：同步后确认第7步持仓台账**未出现在飞书**，且持仓成本/股数/盈亏在飞书文档出现次数为 **0**。
📌 具体校验数字见本地文件，不写进本技能（避免持仓数据出现在可同步的文档里）。
