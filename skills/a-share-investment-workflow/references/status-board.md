# 流程状态表（references/status-board.md）

主技能 `a-share-investment-workflow` 的配套说明。表本体：`$STOCK_DATA_DIR/股票台账/流程状态表.md`；台账模板：`$STOCK_DATA_DIR/股票台账/模板/单股跟踪台账_模板.md`。

## 定位（重要：本表极简）

状态表**只记两件事：哪些股票、各自在第几个阶段**。本工作流明确要求：股票的具体状态（买入几次、卖出几次、成本、买入计划线、卖出线、证据、风险、复盘）**一律写在单股台账里**，状态表不重复、不汇总。

| 文件 | 管什么 |
|---|---|
| `流程状态表.md` | 标的、代码、当前阶段、台账链接、最近更新——就这五列，不再增加状态字段 |
| `持仓中/{股票名}_{代码}_跟踪台账.md` | 该股全部细节：交易明细与次数、成本与盈亏、买入/卖出价格线、证据分层、风险登记、复盘 |
| `组合总览.md` | 组合层集中度、风险贡献、自动任务清单 |
| `投资决策日志.md` | 用户实际动作与当时报告的对照、原话理由 |

## 表结构

1. **在流程中：** `标的 | 代码 | 当前阶段 | 关联台账 | 最近更新`
2. **已移出 / 已清仓：** `标的 | 代码 | 结束原因 | 结束日期 | 历史台账`

阶段写 1–8 步全称（如“第3步 产业链地图与候选池”）；同一只股票只占一行。第8步按每笔交易触发，不单独占行。

## 阶段口径（判定依据，不按时间）

| 阶段 | 名称 | 进入条件 |
|---|---|---|
| 1 | 方向与边界确认 | 用户提出方向或标的线索，双方确认研究范围 |
| 2 | 全球产业分析 | 方向与边界已确认 |
| 3 | 产业链地图与候选池 | 产业分析完成，拆环节、建候选池 |
| 4 | 候选比较与跟踪筛选 | 候选池已建、用户选定标的 |
| 5 | 候选跟踪与买入时机 | 标的进入跟踪、约定买入条件未到 |
| 6 | 买入前讨论与独立核验 | 约定条件达到或接近，用户希望评估该笔 |
| 7 | 建仓承接与持仓管理 | **用户报告实际成交** |
| 8 | 交易后记录与复盘 | 用户报告实际交易结果（与第7步并行） |
| — | 移出 / 不跟踪 | 第5步淘汰，或第4步判定暂不跟踪 |
| — | 已清仓 | 用户报告已全部卖出 |

**阶段由关键证据或约定条件驱动，不由单日涨跌机械切换。** 暂缓后不因信息补齐自动恢复；移出后不自动恢复。

## 维护规则

1. **读：** 用户说“我们开始股票投资工作”或要求“调主流程”、问当前到哪一步／下一步做什么 → 先读状态表，列出全部股票及其阶段（含归档），再回答后续问题。（开场四步固定流程见 SKILL.md《开场协议》）
2. **写：** 仅在**阶段发生变化**时当次更新对应行（新标的进入、阶段推进/回退、移出、清仓）；其它细节变化不改状态表。
3. **细节去向：** 交易次数、成交明细、成本、买入/卖出价格线、证据、风险、复盘 → 全部进单股台账（按模板建档）。
4. **不改写历史：** 已移出/已清仓行保留，不删除。
5. **静默：** 更新状态表不推送通知；自动任务仍按 `ashare-notification-spec` 静默。

## 易错点

- **把状态表写胖：** 加“阶段依据”“下一步条件”“成本”“仓位”等列 → 违反本工作流明确要求，立刻退回五列。
- 只在买入/卖出时更新 → 候选进池、阶段推进、移出、清仓同样要改。
- 用户说“我买了”但未给成交价/数量 → 台账先标待补细节，状态表只把阶段改为第7步；不编造成本。
- 建档时忘记按模板《建档索取清单》向用户要信息（尤其是成交价口径含费/未计费、是否已全部卖出）。
