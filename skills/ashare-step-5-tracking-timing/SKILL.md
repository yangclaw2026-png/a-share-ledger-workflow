# 第5步：候选跟踪与买入时机

主技能 `a-share-investment-workflow` 第5步子技能。标的进入跟踪后持续判断买入时机并维护状态。**跟踪 ≠ 持仓，候选观察提醒与持仓风险提醒分开。**

## When to Use

- 标的经四项检查判定“进入跟踪”。
- 用户问“这只现在能不能买”“到条件了吗”。
- 需要复核某跟踪标的的最新状态。

🔴 **本节优先于本技能其余内容，冲突以本节为准。**

## 跟踪状态（四类，按证据切换）

- **继续跟踪**：逻辑仍成立，但事先约定的经营/估值/走势条件未出现；记录等待证据与复核时间。
- **进入买入前讨论**：约定条件已出现或接近，且用户希望评估当下买入/加仓 → 转第6步。
- **暂缓评估**：重要反证、关键数据疑问，或估值/风险明显偏离计划；暂停未执行批次，记录恢复所需新证据。暂缓保留恢复可能，不等同移出。
- **移出跟踪**：核心逻辑被推翻、业务关联长期无法核实，或缺乏持续跟踪价值；记录原因。出现实质新证据可重新评估，但不自动恢复。

状态变化由证据与预设条件驱动，不因单日涨跌机械切换。股价下跌本身不等于逻辑失效。

## 买入时机四层（分开陈述，不合成总分）

1. 全球市场环境
2. 全球产业方向
3. 板块/产业链资金轮动（相关性不是资金因果；单日涨跌不足以确认轮动）
4. 个股位置

## 技术指标

MA5/10/20/60、RSI14（Wilder 平滑）、MACD（EMA12−EMA26，DEA=EMA9(DIF)，柱=DIF−DEA）；用全样本 warm-up 再取最新值，全部用代码算、不靠记忆。技术面只作辅助预警，不单独导出买卖结论。指标报告另见 `finance-stock-technical-analysis`。

## 方向起点基准（新增·必做）

第5步建台账时，若**同一方向有多只跟踪标的**，必须记录「方向起点基准」。

**定义**：以用户指定的起点日（默认该方向研究启动日）计算各标的到当前的实际涨跌，给出方向内排名与相对中位的差值。

**为什么必须做**：单只标的涨跌无法判断对错——同一方向里业绩最差、估值最贵的往往涨得最多。实例：标的甲在某区间涨近八成，但归母九成以上靠非经常性损益、经营现金流为负、PE 超百倍，已被排除。**方向内相对强弱才是可用信号。**

**记录内容**：
1. 全方向起点回溯表（各标的起点价、当前价、涨幅、排名）
2. 本标的的位置：排名 N/M、方向中位、相对中位差值（pt）
3. 解读规则：持续跑输方向中位且无公司端新证据 → 相对强弱转弱，需重评是否继续跟踪；跑赢 → 方向内首选参考

**红线**：起点日必须由用户确认或取该方向研究启动日；**不得事后挑选有利起点来美化结论**。

## 起点回溯验证

方向裁定完成后，用「起点→当前」回溯验证方向层面的判断是否与市场一致。

- 已验证实例：方向甲裁定「无一进门槛（区间内多家经营现金流全负）」，而它同期涨幅在全部方向中垫底；方向乙裁定「只留估值分位达标标的」，方向均值远低于其他成长方向。**两项均被市场表现印证。**
- 发现不一致要正面记录，不得回避（例：某方向 PB 分位最低，但区间涨跌为负）。

## 门槛合同（机器可判定·cron 依赖）

第5步的“买入时机”必须写成**可量化的门槛合同**，否则 cron 无法识别触发。第5步台账建立时就要写全，不要事后补。

### 必过项（排除项，达不到坚决不推荐）

| 编号 | 判定标准 |
|:-:|---|
| **A1** | 扣非净利同比>0 **且** 经营现金流>0 **且** 现金流同比>0 |
| **A2** | 无 B 层失效证据（价格下跌、跌破均线、异常放量**不算**失效）|

三项口径缺一不可：只用“扣非>0”会放过现金流大幅恶化的公司（实测三只均属此类）；扣非同比为负时无论原因都算不达标（不因“一次性收入基数消失”豁免）。

### 触发项（B1–B5 任一满足即提醒）

| 编号 | 判定标准 |
|:-:|---|
| **B1** | 距 60 日最高价回撤 ≥25% |
| **B2** | 已跌破 MA60 |
| **B3** | PB 分位 <75%（剔上市首年口径）**或** PE 分位（近3年）≤50%（且扣非占归母 ≥90%）|
| **B4** | 相对方向中位差值 ≥0（不再跑输）|
| **B5** | 站上 MA20 且 MACD 金叉 |

B1 与 B2 是**或**关系，不是同时满足。

### B3 为什么是双口径

B3 管的是「估值到了可看的位置」这一个信号，但**两类标的要用两把尺子**：

- **PB 口径**（<75%）：用于低 ROE 周期股 —— PB 不受盈利波动干扰。
- **PE 口径**（近3年 ≤50% 且扣非占归母 ≥90%）：用于高 ROE 成长股 —— 它们净资产积累追不上股价，**PB 分位结构性偏高、永不触发**；真正在动的是 PE。
- 「扣非 ≥90%」是 PE 口径必要限定：防 PE 低来自一次性收益（PE 口径唯一漏洞）。
- ⛔ **不加「无🔴强周期标签」限定**：ROE 极差是累积指标，标签一旦命中不可逆 —— 用「历史波动」永久否决「当下机会」。要防的周期股已由 A1 现金流门槛拦下。

### 决策权

门槛命中只是**提醒**，不代表买入建议。进入第6步（买入前核验）必须由用户主动决定，助手不得自动推进、不得自动下单。

### 计算实现

判定用脚本一次算完：`scripts/candidate_gate.py`，输出 JSON 的 `alert` 数组。
cron **`候选监控｜候选门槛复查`**（示例：周二+周五 08:20，按需自建）｜🔴 **引用写完整任务名，不写 cron ID**。

**门槛拦住的都是真问题**：某方向实测中，被拦下的分三类 —— 扣非增长但现金流恶化、现金流为负、扣非负增长。只用单一条件会放过后两类。

**⚠️ 已知边界**：「扣非占归母 ≥90%」会挡住一批 80%–85% 区间标的的 PE 分支；其中 A1✅A2✅ 的只能靠 B4 触发。阈值是否放宽到 80% 留待后续。

**🔴 提醒必须带警示**：如扣非含大额技术授权收入（非纯商业化）、整体亏损且 PB 分位全场最贵，都要在提醒里点名。

## 🔴 新股（上市不足 3 个月）：技术面不可判定，必标“待累计”

台账里遇到上市不足 60 个交易日的新股，铁律：

1. **K 线 < 60 根 → B1/B2/B5 一律写“⚠️ 待累计”，禁止写“未触发”**。MA60、60日回撤、MACD 均无法计算，写“未触发”是隐型误报。
2. **估值分位样本 < 200 条 → 标“统计意义不足”**，不可当达标依据（与北交所样本不足同理）。
3. **上市初期涨幅不参与方向内比较**（起点回溯里独立列示，不排名）。
4. 脚本 `candidate_gate.py` 遇到不足 60 根 K 线会返回 `action=DATA_FAIL` 且 `reason` 明写“待累计满60个交易日”（不是崩溃、不是排除）。
5. 台账“待办”里写下**具体重跑时点**（上市满 60 交易日）。

## 🔴 链条完整性：必须做“概念反查”补漏

建完产业链链条后，**必做一次概念反查**：拉候选标的的概念标签对比链条，防止整层整层漏列。

- 某方向就漏了一整层：**分销/系统层**＋利基二线＋主控第二家。
- 补漏后直接改变方向结论：原“0 只进第5步” → **两只二线标的硬门槛双通过**。
- 反查方法：东财 `RPT_F10_CORETHEME_BOARDTYPE`（filter=`(SECUCODE="600000.SH")`，换成你的标的）取概念标签；东财概念板块因为混入大类不可直接用。

## 🔴 同一环节内部现金流会相反

“存储全链条现金流全负”只对**模组厂**成立；设计端与分销端在涨价周期里**先收钱、现金流转正**：

| 环节 | 代表 | 经营现金流（示例为虚构数，仅示意量级差异） |
|---|---|---|
| 模组厂 | 标的A/B/C | **全负** |
| 设计端 | 标的D | **+0.61亿**(+51%) |
| 分销＋存储 | 标的E | **+57亿**(+1250%) |
| 晶圆制造 | 标的F | **+1311亿**(+2985%) |

教训：**不得用一家的现金流代表一整个方向**；A1 必须逐只算。

## ⭐ 纳入新标的的标准动作（建台账即自动纳入）

```
建 1 份台账 股票台账/候选/<名称>_<代码>_跟踪台账.md
   ├─ 候选门槛复查  ✅ 自动纳入（扫目录）
   ├─ 台账同步飞书  ✅ 自动纳入
   └─ Q3 披露监控   ✅ 自动纳入（扫目录）
```

⭐ **自动的依据**：三个脚本都用 `os.listdir(台账目录)` / `glob("*_跟踪台账.md")` 决定跑哪些标的，建台账即纳入，不改任何 prompt。
🔴 **已修的隐型陷阱**：原先 `candidate_gate.py` 纳入条件是 `if code in PB_PCTL` —— **忘补门槛数据 = 静默跳过**，新标的无声无息不在监控里。现改为「全部纳入，缺数据报 `NEED_DATA` 并列出缺哪几项」。

### 必须补门槛数据（不能省）

在 `$STOCK_DATA_DIR/bench.json` 的 `stock` 里为该标的加一条（**7 项字段**）：`direction`、`bench_pt`（B4 相对强弱）、`pb_pctl`、`pe_pctl_3y`、`kf_ratio`、`a1`（`[扣非同比, 现金流亿, 现金流同比]`）、`a1_note`。
字段含义与示例见 `templates/bench.example.json`。

⚠️ **`a1` 无法自动生成**：扣非/现金流必须读财报正文（正则抽取准确率仅 3/8，见 `ashare-data-source-fallbacks`）；`bench_pt`/`pb_pctl`/`pe_pctl_3y` 可脚本重算。

### 跑校验

1. `python3 scripts/validate_ledgers.py`（应全通过）
2. `python3 scripts/candidate_gate.py` 确认只数增加，**且新标的不是 NEED_DATA**

⚠️ **脚本身份**：`candidate_gate.py`/`q3_watch.py`/`validate_ledgers.py` 是**仓库 `scripts/` 里的唯一一份**；
而 Hermes cron 的 `--script` 类脚本（如 `profit_guard.py`）**只能放在 `$HERMES_HOME/scripts/`**（cron 硬性要求），
改完仓库版必须 `cp` 过去才生效 —— 两份不一致时校验器**第12项会报「脚本漂移」**，别只改一处。

## ⭐ 定期“按新口径重筛”的标准动作（应用户要求或口径变更后）

1. **不要直接引用方向档案里的 PE 分位** —— 那些是**全历史**口径；B3 要的是**近3年**。两者常年相反（实测某标的：全史 63.8% vs 近3年 81.4%）。
2. 统一重算：东财 `RPT_VALUEANALYSIS_DET` 日度 PE_TTM/PB_MRQ（每个代码 pageSize=500 翻页至空），按当前值在序列中的百分位取数。
3. **A1 必须用同期金额对比**，不要用 `MGJYXJJETZ`（详见 `ashare-data-source-fallbacks`）。
4. 交叉判定：`A1✅ 且 B3✅` → 才谈得上进第5步；再叠加 **A2（业绩质量/失效证据）**与业务逻辑。
   - ⚠️ **低 PB 不等于便宜**：先看是否为「净资产被减值过」或「周期底低 PB」（盈利极弱）。

## 复核节奏

- 方向与产业至少每周回顾；个股不要求每日长篇分析。
- 关键经营数据、公告、估值条件或约定买入信号变化时重点复核。
- 无足以改变判断的新信息则静默；重大变化提前复核。

## 跟踪记录字段

每只标的记录：当前阶段、进入日期、依据、关注数据、下一步条件、失效/淘汰条件。

## 方法与教训

- 把假设拆成传导链逐环验证，不整体接受或否定；结论写成“哪一环成立”。
- 全市场共性变量不能当个股买入理由（成交量回升是全市场现象），个股上涨取决于自身景气与板块风偏。
- 用户观察常方向对、精度差；把笼统说法拆成可量化条件再逐环检验。

## 输出与停止条件

输出状态 + 等待证据 + 复核节点即停；条件达到且用户希望评估时转 `ashare-step-6-prebuy-gate`。

### ⚠️ 金融股例外：现金流门槛对券商/银行/保险失效

**金融股的「经营活动现金流」含客户保证金/存款变动**，行情好时是巨大正数，**不代表盈利质量** —— 曾实测某券商经营现金流超 +1000亿，而另两家同期为 **−40亿量级**。

🔴 **后果：A1 的现金流门槛对金融股全部放行**，而它本应拦下「周期顶部利润」。

**周期顶部识别改看三项**（不用现金流）：
1. **自营/投资收入占比**（最不稳定的收入）—— 曾实测某券商该占比近四成、另一家近五成
2. **PE 分位极低（<10%）** —— 在金融股身上是「周期顶部利润」的镜像，**不是便宜**
3. **市场总成交量/活跃度** —— 券商收入总开关（曾实测牛市日均成交额达熊市低点近 3 倍）

## 🔴 阶段变更 = 更新流程状态表（三层保障）

标的进出本步（新增／移出／降级／清仓）时**当次**更新 `股票台账/流程状态表.md` 对应行，只写「名称 (代码)」；细节进单股台账。🔴 **同一代码不得出现在多个阶段行。**

三层保障：① 本要求；② `validate_ledgers.py` 台账↔状态表双向一致性（跨行重复／有台账未登记／标第5-7步但无台账）＋台账正文↔`bench.json` 门槛数据一致性；③ 周一 08:12 `台账同步`（no_agent）自动跑校验，不一致→飞书告警。

🔴 目录与 cron 是自动扫描的（建台账即纳入），**只有流程状态表是手工的** —— 唯一会漏的环节。
