# 第2步：全球产业分析

主技能 `a-share-investment-workflow` 第2步子技能。方向与边界确认后，围绕用户方向做产业层研究：只出产业证据与前瞻判断，不下个股结论。

## When to Use

- 第1步边界已确认，进入产业研究。
- 用户要求补充/更新某方向的产业证据。
- 第5步跟踪中需要复核产业前提是否变化。

## 🔴 执行纪律（本工作流强制·优先级最高）

🔴 **本节优先于本技能其余内容，冲突以本节为准。**

### 本步不可跳过的项

| # | 强制项 | 不做会怎样 |
|---|---|---|
| 1 | **每条产业结论必须带：来源 + 发布日期 + 口径** | 没口径的数字会在下一轮被当成另一个东西引用 |
| 2 | 全球视角要求：**至少 2 个海外同环节来源**，不是只看国内 | 只看国内容易把周期顶部当成长 |
| 3 | 区分：已核实事实 / 推断 / 假设 / 待核实 | 混在一起就分不清哪句话有证据 |

## 本步产出

- 相关市场清单与选择理由（按产业链关联，不限于中国）。
- 六类证据：需求 / 供给 / 价格 / 技术路线与替代 / 资本开支 / 政策与贸易限制。
- 每条证据带来源、日期、单位、口径、比较窗口。
- 传导路径：产业信号 → 环节 → 公司业绩，逐环说明。
- 前瞻判断：可能变化的方向、时间窗、触发信号与证伪条件。
- 待核实清单（哪些结论只有二手信息）。

## 执行步骤

1. 按用户方向的产业链，列出真正相关的市场与对标（例：存储→韩/美；半导体→美/港/韩）。
2. 逐类检索六类证据，优先一手资料（公司公告、协会数据、财报、官方数据）。数据获取与解析方法见主技能 `a-share-investment-workflow` 下挂的《数据源、引用规范与历史对比铁律》参考文件。
3. 每条证据标注来源、日期、单位与口径；二手摘要不得当一手事实。
4. 画传导链，逐环标出证据强度，指出最薄弱那一环。
5. 给出前瞻判断与证伪条件；未验证部分明确标“待核实”。
6. 输出后停在产业层，不进入选股。

## 全球视角要求

- 市场环境与产业方向扩展到海外重要市场，不限于中国。
- 对标要说明价格、汇率、时区、业务口径差异；海外走势是证据之一，不自动等于A股个股的涨跌因果。
- 假期期间海外仍在交易，是A股开盘的前瞻信息。

## 重要提醒：用户手动触发要求

> 本步骤**不设定时任务（corn）**，仅在流程状态表中留下标的提醒。
> 当流程状态表显示有标的处于本步时，请用户明确指令：
> "手动执行 [步骤2] 的 [具体标的名] 任务" 或 "查一下 [方向名]"
> 我将按需启动一次性分析，完成后不残留任何定时任务。

## 边界

- 不选股、不给候选名单、不做买卖判断。
- 不把单一来源或二手媒体报道写成确定事实。
- 相关性不等于资金因果；单日涨跌不足以确认轮动。

## 输出与停止条件

产业证据 + 传导链 + 前瞻判断 + 待核实清单齐备即停，移交第3步 `ashare-step-3-chain-pool`。

## 🔴 阶段变更 = 更新流程状态表（三层保障）

标的进出本步（新增／移出／降级／清仓）时**当次**更新 `股票台账/流程状态表.md` 对应行，只写「名称 (代码)」；细节进单股台账。🔴 **同一代码不得出现在多个阶段行。**

三层保障：① 本要求；② `validate_ledgers.py` 台账↔状态表双向一致性（跨行重复／有台账未登记／标第5-7步但无台账）＋台账正文↔`bench.json` 门槛数据一致性；③ 周一 08:12 `台账同步`（no_agent）自动跑校验，不一致→飞书告警。

🔴 目录与 cron 是自动扫描的（建台账即纳入），**只有流程状态表是手工的** —— 唯一会漏的环节。
