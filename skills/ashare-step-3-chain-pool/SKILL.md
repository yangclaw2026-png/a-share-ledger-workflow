# 第3步：产业链地图与候选池

主技能 `a-share-investment-workflow` 第3步子技能。把产业分析落到具体公司，产出一份可供用户挑选的候选池。

## When to Use

- 第2步产业证据完成，需要落到标的。
- 用户要求扩充/清理候选池。

## 🔴 执行纪律（本工作流强制·优先级最高）

🔴 **本节优先于本技能其余内容，冲突以本节为准。**

### 本步不可跳过的项

| # | 强制项 | 不做会怎样 |
|---|---|---|
| 1 | 每只候选写清 **入池依据** | 没依据 = 下一步无法判断该不该筛它 |
| 2 | 每只候选写清 **移出条件** | 没移出条件 = 坏公司永远留在池子里 |
| 3 | 拆分产业链环节，标出**本方向真正赚钱的环节** | 全产业链都当机会 = 候选池稀释 |
| 4 | 反跳步规则：不得从第1步直接跳到本步建候选池 | 未确认方向就建池 = 整个池子可能建在错的方向上 |

### 本步专属红线

**候选池不能靠「听说这家公司不错」扩充。** 必须能写出它在哪条传导链上。

> 全局三条硬规则（不凭记忆执行／跳过须显式写明／缺数据就停下来报）见主技能
> `a-share-investment-workflow` 《执行纪律》一节。

### 收尾自查

- [ ] 每只候选都有入池依据 + 移出条件
- [ ] 产业链环节已拆，标注了哪个环节是本方向的核心
- [ ] 没有从第1步直接跳来（方向已确认）
- [ ] 已停在第3步，**未自动进入第4步**

## 本步产出

- 产业链环节拆解（上游材料/设备/器件 → 中游制造 → 下游应用）。
- 每个环节的代表公司及与用户方向的关联方式。
- 候选池：入选公司 + 入选理由 + 跟踪指标 + 淘汰条件 + 入选日期。

## 执行步骤

1. 按环节拆链条，标出用户方向直接对应的环节。**链条必须从上游原材料/设备开始拆到下游应用，不允许只拆中游。**
2. 候选公司要核实业务是否真的相关：读年报“主要业务”章节，不凭印象、不凭概念。
3. 优先产业链上游/“卖铲子的”环节（用户偏好）；报告常点的模块厂/龙头恰恰是他要避开的。
4. 每只候选手工登记：入选理由、跟踪指标、淘汰条件、入选日期，保证可回溯验证。
5. 池子交用户，由用户选择要进一步看哪家公司；助手不替用户选定标的。

## 🔴 反跳步规则（2026-10-05 新增，因实际发生过的错误）

**不得跳过本步直接做估值分位或建台账。**

- 实际发生的错误：方向09（国产芯片制造）在第1步后直接跳到“算13只标的PB/PE分位 → 建台账”，**第3步从未执行**，导致：
  - 整条上游设备/材料层未进入视野；
  - 11只候选中只有3只读过半年报“主要业务”，其余靠常识列名，违反本技能红线；
  - 后续某标的进第5步带有偶然性（跳步的运气，不可复制）。
- 正确路径：第1步 → **第2步（含链条拆解）** → **第3步（链条地图＋候选池，逐只核实业务）** → 第4步筛选 → 第5步跟踪。
- 判断是否跳步的信号：候选公司名单是“按环节一句话列出名字”而**没读过其年报业务章节**，即为跳步，须退回本步。
- 若已跳步并建了台账：必须回到本步重做候选池，**并重算分位**（池子变了，分位结论可能失效）。

## 重要提醒：用户手动触发要求

> 本步骤**不设定时任务（corn）**，仅在流程状态表中留下标的提醒。
> 当流程状态表显示有标的处于本步时，请用户明确指令：
> "手动执行 [步骤3] 的 [具体标的名] 任务" 或 "查一下 [方向名]"
> 我将按需启动一次性分析，完成后不残留任何定时任务。

## 硬要求与红线

- 日报/周报点名的股票不得直接进池；不采用别人给的名单。
- 候选池筛选逻辑要能由代码计算（估值分位、波动、流动性、盈利质量等），不靠模型记忆；该机制尚待与用户确认后实现。
- 候选 ≠ 持仓；进池不等于买入。
- 公司公开收入分类里没单列相关业务的，明说“无法仅凭公开披露量化”，不模糊带过。

## 输出与停止条件

环节地图 + 候选清单（含入池/淘汰条件）产出后停，交用户选定标的；选定后进入第4步 `ashare-step-4-candidate-screening`。

## 🔴 阶段变更 = 更新流程状态表（三层保障）

标的进出本步（新增／移出／降级／清仓）时**当次**更新 `股票台账/流程状态表.md` 对应行，只写「名称 (代码)」；细节进单股台账。🔴 **同一代码不得出现在多个阶段行。**

三层保障：① 本要求；② `validate_ledgers.py` 台账↔状态表双向一致性（跨行重复／有台账未登记／标第5-7步但无台账）＋台账正文↔`bench.json` 门槛数据一致性；③ 周一 08:12 `台账同步`（no_agent）自动跑校验，不一致→飞书告警。

🔴 目录与 cron 是自动扫描的（建台账即纳入），**只有流程状态表是手工的** —— 唯一会漏的环节。
